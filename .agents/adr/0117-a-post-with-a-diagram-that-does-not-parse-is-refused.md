# 117. A post with a diagram that does not parse is refused

2026-09-18 · widens 112; relates to 62

**Context:** a mermaid diagram with a syntax error, in a `mermaid` block or a ```mermaid fence inside markdown, landed as mermaid's own bomb graphic on the reviewer's page while the post returned 200 and the packet said nothing, so the reviewer judged a figure that was not there and the agent heard nothing until submit — the shape ADR 112 had already refused for a failed reference. **Decision:** the daemon parses every diagram a post or an amend carries with the same vendored engine the page draws with, in a sealed `vm` context, before anything is stored; one that does not parse refuses the post whole with one message per failing diagram naming where it sits, the engine's first error line with its line number, and the ways out, joined with any reference-refusal messages; a diagram over mermaid's own 50,000-character limit is refused unparsed, and a failure inside the engine that is not a parse error lets the diagram through. **Consequences:** the daemon holds the engine in memory (about 75 MB) after the first diagram it checks and may stall a few seconds on a pathological diagram at the limit; a fence in a referenced file the agent does not own refuses every post that references it until the file is fixed or the section goes up by value with the fence marked as code; the page-side error graphic stays for boards stored before this and for the rare draw-only failure.
