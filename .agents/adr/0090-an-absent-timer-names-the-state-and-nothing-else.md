# 90. An absent Timer names the state and nothing else

2026-08-11 · completes 88; relates to 83

**Context:** ADR 88 made the Popover's line the index page's line in every state, but idle was left out of that sweep and stayed as the one state where the two surfaces disagreed — the index page said `Idle (25 min)`, naming the configured work length, while the Popover said the bare `Idle`. The bracketed duration was a deliberate earlier call (a spec asking for "the durations, or a dash"), made to keep an idle widget from reading as an error; it survived only in a check's own assertion once that spec landed and was deleted. **Decision:** an absent Timer renders `Idle` on both surfaces, with no duration. A number that is not counting down, sitting where a countdown sits, reads as a countdown that has stopped — the reasoning `cb_derive` (`bin/menubar.m`) already used to keep the work length out of the menu bar, now applied to the widget that had it. The configured length stays one field away in the settings panel, which is where a number a reader can edit belongs. **Consequences:** ADR 88's "in every state" is now true without exception, and the cross-surface check compares idle like any other state rather than carving it out; the reader loses the at-a-glance answer to "how long is a work interval" and has to open the panel that sets it.
