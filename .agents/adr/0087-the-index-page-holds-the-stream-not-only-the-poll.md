# 87. The index page holds the stream, not only the poll

2026-08-10 · amends 77; relates to 86

**Context:** ADR 77 refused the index a live connection on two premises: the index is "a page nobody stares at," and a stream costs one held connection per open tab, indefinitely, for however many tabs get left open. The first premise stopped holding once entry 86 shipped the popover: the reviewer now acts on a board from the menu bar while the index page sits open on screen, so a press there needs to reach a page someone is, in fact, watching. The push spec that built 86 wanted the two surfaces to agree within a second in either direction and knew it was shipping only half of that; the index side was left for later because the stream it would need did not exist yet.

**Decision:** the index page subscribes to the same daemon-wide stream (`GET /api/events`) the menu bar already holds, alongside its fifteen-second poll rather than in place of it. Reconnect is the browser's job: `EventSource` already reconnects on its own, the same trust the board page places in it, and the menu bar's hand-written backoff exists only because it speaks raw HTTP from Objective-C, so there is no second backoff to write here. A push carries only a signal, never the state itself: a `waiting` event wakes the same fetch against `GET /api/index/rows` the tick already runs to patch the list, and a `pomodoro` event wakes the same fetch against `GET /api/pomodoro` the widget already runs to reconcile its clock. Either way, the push wakes the one fetch that already owns that piece of state rather than gaining a second writer of its own. The tick itself is untouched: it is the fallback for a stream that never connects or drops and stays down, and, separately, it remains what re-labels "a minute ago" into "two minutes ago" on rows nothing has changed, which is ADR 77's bucket reasoning and no part of what this entry reverses. Only a row change the daemon actually broadcasts gets the fast path; a prune, a board going stranded, or a last-activity stamp drifting on its own has no event behind it and keeps arriving on the tick exactly as before. Broadcasting those too is a separate decision.

**Consequences:** every open index tab now costs one held connection, the shape a board tab has always cost, for as long as the tab stays open, accepted because a reviewer keeps few index tabs and because once the per-tab cost is back on the table the only alternative that closes the same gap is a shorter poll, not a smarter one. The two surfaces agree within a second in either direction, and an index left open through a daemon restart comes back live on its own the way the menu bar already does. ADR 77 keeps standing for what this entry never touches: the tick, its role as fallback, and its bucket relabeling.
