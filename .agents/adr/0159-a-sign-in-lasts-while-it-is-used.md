# 159. A sign-in lasts while it is used: 400 days, renewed, SameSite=Lax

2026-11-24, narrows 118; replaces the 30-day cut of 2026-07-31, which had no entry (it was a comment in `src/secret.mjs`); relates to 158

**Context:** the session cookie lived 30 days from its sign-in and was never renewed, so every browser signed in again each month, which with away devices is one link per device per month. The 31 July cut from 400 days to 30 bounded how long another server on the same host could go on replaying a copied cookie through an honest browser; the value itself carries no date, so a copy never expired either way. **Decision:** `Max-Age` is 400 days, the longest a browser keeps a cookie, and the daemon sends the cookie again on each request it authorizes, so a browser used once in 400 days stays signed in. Not renewed: a stream, a request from another site, a prefetch, a route that asks for no credential, a request carrying the secret. One value signs in the loopback names and the away name, with `Secure` on the away name alone. `SameSite` is `Lax` in place of `Strict`, because a board link tapped in another site's page has to arrive signed in; what `Lax` lets through besides is refused in the daemon (`isLinkTap`): another site may open `/b/<id>`, as a top-level page and with a GET, and reach nothing else, the lists above all, whose cards answer in one click. **Consequences:** accepted: any other http server on the same host receives the cookie, for as long as the browser is used rather than for a month, and a value taken on one origin works on the other; a lost phone stays signed in. Rotating the secret is the one thing that ends a sign-in, and it ends every browser's at once. 118's login once a month is once.
