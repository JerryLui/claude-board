# 100. A re-install prints twelve lines, and the standing prose is first-run-only

2026-08-11 · relates to 36

**Context:** `install.sh` printed about forty-five undifferentiated lines on every run, and `README.md` makes re-running it the way to take a code change, so the wall was the steady state rather than a first-time cost. Three standing macOS paragraphs, a six-value config header of mostly defaults, and raw output from `codesign` and the Claude CLI accounted for most of it. **Decision:** the default run prints one line per step plus a short summary, roughly twelve lines; the standing prose prints in full only on a run where the thing it describes is new, third-party output is captured and surfaced only when its step fails, the header shows only non-default values plus the port, and `--verbose` restores every one of those. **Consequences:** this reverses the argument written into the script's own comments, that whoever hits a TCC failure rarely watched the install scroll past — a pointer line and `--verbose` carry that reader now; the widen line entry 36 calls load-bearing survives the header cut only because a widen is by definition non-default, so folding the header further would break it; and roughly thirty stdout assertions in `test/check-install.mjs` are rewritten against the new output.
