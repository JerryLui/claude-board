# 76. A launch that did not come from launchd refuses to supervise

2026-08-10 · relates to 75

**Context:** the bundle with no arguments is the daemon supervisor, and a notification click that finds no serving process can have LaunchServices start the bundle exactly that way, which on a default-port install loses the port and dies within a second but on one with a custom port becomes a second live daemon over the same store, with its own banners and its own pomodoro timer racing the real one over one file, until someone kills it. **Decision:** the supervising path refuses to run when it was not started by launchd, keyed on something launchd itself provides rather than on an argument, because the one invocation that must never depend on getting argv right is launchd's own. **Consequences:** running the launcher by hand to supervise a daemon stops working and must go through launchd, which is a real cost to entry 72's work where a bundle child was measured launched from a shell as well as bootstrapped by launchd, the refusal has to be silent enough that a stray LaunchServices launch is a no-op rather than a dialog, and only the no-argument supervising path refuses, leaving `--notify` and `--menubar` untouched.
