# 95. Mermaid is vendored, closing the CSP's last external-host allowance

2026-08-11 · widens 62; relates to 70

**Context:** entry 62 vendored `marked` and `prismjs` because both run server-side at post time and this repo has no bundler to fetch them through; mermaid was left alone because it runs client-side and was `import()`-ed from `cdn.jsdelivr.net` at view time instead, the one remaining piece the CSP had to name an external host for at all (`script-src`/`font-src` both carried a version-pinned `cdn.jsdelivr.net/npm/mermaid@<version>/` prefix) — version-pinned but not byte-pinned, since a dynamic `import()` cannot carry an `integrity` attribute, so a compromised jsdelivr could have served different bytes at that exact path and reached read-every-board plus forge-an-answer on every board rendered after it. **Decision:** vendor mermaid 11.16.1's single self-contained `dist/mermaid.min.js` build (not the ESM entry, which lazy-`import()`s 103 further chunk files, ~3.49MB, against this build's one 3.4MB file with none) into `src/vendor/mermaid/`, digest-pinned in the same manifest entry 62 established. Unlike `marked`/`prismjs`, mermaid still has to run client-side, so it ships as a third content-addressed sibling asset (entry 70) rather than an import the daemon resolves itself — loaded via a dynamically inserted classic `<script src>`, never `import()` (mermaid's build only works under classic-script global scoping, and a module fetch is CORS-gated over `file:` regardless of same-origin-ness either way), fetched only when a board actually has a diagram. **Consequences:** the CSP's `script-src` and `font-src` drop their one CDN allowance outright rather than re-pin a version — no clause in the policy names an external host any more, and a board with a diagram renders with the network off, on both the served and Finder surfaces. An archive is now three sibling files, not two (entry 70's cost, widened). And a prune's asset sweep has to scan every surviving asset's own bytes, not just every page's, because mermaid is named only by `ui.js` — on demand, never by a page's own markup — so a page-only scan would reclaim a still-used engine. The accepted cost: a mermaid diagram *inside an `html` stage* no longer renders at all. A stage is `sandbox="allow-scripts"` with no `allow-same-origin`, so it runs at an opaque origin where `'self'` matches nothing and the vendored sibling is unreachable; the dropped CDN clause was a *host* source, which does match from an opaque origin, and was the only thing that ever let a rendered artifact draw its own diagrams. Those now degrade to raw mermaid source, immediately and unconditionally. Re-admitting the host would hand back the exact read-every-board-and-forge-an-answer exposure this entry exists to close, and the only alternative that keeps it out — inlining the engine into each stage's `srcdoc`, ~3.4MB per stage inside the stored board document — was weighed and declined.
