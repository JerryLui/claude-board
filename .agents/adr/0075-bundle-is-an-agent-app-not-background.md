# 75. The bundle is an agent app, not a background-only one

2026-08-10 · narrows 57; relates to 72

**Context:** entry 57's click works, in that the delegate fires and the board opens, but macOS also brings the posting app to the front to hand over the response and `LSBackgroundOnly` declares an app that may never be brought to the front, so every click also fails activation with `-600` and puts *"The application claude-board.app is not open anymore."* on screen, the plist and the click-serving process contradicting each other since that process already asks for the accessory policy at runtime. **Decision:** the bundle declares `LSUIElement` instead, an agent app with no Dock tile and no menu bar but one macOS may bring forward, rather than serving the click from a second bundle or dropping the click. **Consequences:** the bundle's bytes move, so it is rebuilt and re-signed and the reviewer re-approves the Documents folder once (QUIRKS.md, "the grant is pinned to the code signature"), the notification identity does not move so the System Settings row and the existing authorization survive, a successful activation is what makes entry 76 necessary, and entry 72's status item, measured visible under `LSBackgroundOnly`, should survive on the reasoning that an agent app is the standard host for a status item, which is inference the landing session owes a measurement for since both entries move the same plist.
