# 108. The board lends its engine to a marked stage

2026-08-19 · widens 95; relates to 70

**Context:** entry 95 accepted "a stage's diagrams degrade to raw source" as the cost of dropping the CDN host clause, on the belief that the vendored sibling is unreachable from a stage's opaque origin. Measured in Chrome (static probe mirroring the exact page CSP and `sandbox="allow-scripts"` srcdoc, 2026-08-19), that belief was half wrong: a srcdoc document inherits the parent's base URL and the parent's CSP with `'self'` still bound to the parent's origin, so a bare sibling `<script src="mermaid-<hash>.js">` inside a stage resolves to `/b/<name>` and is admitted — served. What actually refused it in production was the credential gate: a fetch from an opaque origin carries no `SameSite=Strict` cookie and answered 401. Over `file://` the same tag can never load and no CSP spelling changes it — Chrome's local-resource rule grants `file:` subresources only to file:-origin contexts, and `allow-same-origin` is not a lever this repo pulls. **Decision:** a stage whose bytes carry the mermaid class marker gets the engine from the board, injected once into its srcdoc ahead of the stage's own scripts, two ways: the bare sibling tag first (the real engine, synchronous — the served surface), then an inline prelude that shape-checks what arrived and, when the real engine did not, installs a `window.mermaid` facade — same API surface, rendering by messaging the diagram source to the parent, which runs the vendored engine (as board-level mermaid always could, on both surfaces) and returns the SVG, swapped in only on success. Either way `window.mermaid` exists before stage scripts run, so an artifact's `if (!window.mermaid)` loader short-circuits unmodified. `isOpenRoute` gains its one asset exception: a credential-less GET for a `mermaid-<hash>.js` name — public library bytes, a content-addressed name derivable from those public bytes, weaker disclosure than the already-open `/api/health`. **Consequences:** every past /explain artifact renders its diagrams again on its next post, unmodified, and entry 95's supply-chain closure stands — no CSP clause names an external host and nothing ever leaves for one. Diagram-free pages stay byte-identical; a marked stage's page grows by a tag and a compact prelude, never a 3.4MB engine. The artifact contract (SKILL.md) gains a mermaid-only exception to "one self-contained file". The parent's render service is a trust boundary — stage messages are hostile input: payloads validated, config allowlisted (`securityLevel` never forwardable), engine state re-initialized per batch so a stage cannot restyle board-level diagrams. A stage that builds its diagram DOM at runtime misses the textual marker and keeps raw source, accepted.
