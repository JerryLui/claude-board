# 122. A page carries each stage once

2026-10-19, amends the last consequence of 121; relates to 32, 42; narrowed by 136

**Context:** ADR 121 let an html stage reach 25 MB, and the page carried it three ways at once: in the frame's `srcdoc`, in the board data the page script hydrates (`#board-data`), and again in the board every live push carries. A 20 MB stage served a 40 MB page, a Send pushed 40 MB to every open tab (the round's markup with the stage, and the board with it again), the tab's own catch-up read on each connect fetched the 40 MB page a second time, and the tab replaced the round a Send pushed back, frame and all, so a paused video went back to its start. Nothing in the page script reads a stage's html off the board: the Lens copies the frame's own `srcdoc`, and the push diff needs only to see that a stage changed. Media served by reference from the daemon was out of scope. **Decision:** the page's own copy of the board (`#board-data`, and every push's `board`) leaves out every html block's `html`, wherever the block sits, and keeps its `sha`; every stage frame names its content by that sha (`data-sha`); a push sends a stage the tab already holds empty and marked held (`data-held`), so a Send sends every stage held and an amend sends held, in each block it re-posts that already sat in the open round, each stage that block held before, keyed on the sha because an amend re-mints the ids of nested blocks; the tab's catch-up read asks for the page with every stage held (`?stages=held`); and the page script keeps a live frame wherever a push's markup names the same sha in the same place, making the markup over around it rather than replacing it, since a frame taken out of the document reloads. A held frame no live frame can stand for is filled by one read at a time of the page with those stages alone whole (`?stages=<sha>,...`), each stage going only into a frame that names its sha. A push holds stages only for a tab whose event stream declares it can fill a held frame (`?stages=held`): a tab still running a script from before this gets every stage whole and the board with each stage's html, the copy that script diffs against, and so does its catch-up, a script's fetch of the plain page (`Sec-Fetch-Dest: empty`). Rejected: keeping the html and accepting the size; leaving it out but replacing the frame on every push, which keeps the bytes down and still loses the mock's state; moving the frame with `moveBefore`, which keeps a frame's state in Chrome alone. **Consequences:** a 20 MB stage serves a page of about 20 MB, a Send's push is a few kilobytes, and a paused video keeps its second through a Send; a push and a later full reload carry the same board bytes and differ only by a held frame, empty in the push; an archive's `#board-data` no longer carries the stage's markup (its frame still does); a tab opened before an upgrade to this keeps the cost it had, every stage in each push and twice in its catch-up, until it is reloaded, and in a browser that sends no `Sec-Fetch-Dest` its first catch-up reloads each stage once; two frames under one block that name the same sha are kept in document order, so an amend that drops the first gives the second the first one's live frame, the same content with the first one's state (a video's second); a kept stage keeps the fold its own reports gave it, where a reload would mark a stage holding a sent comment opened.
