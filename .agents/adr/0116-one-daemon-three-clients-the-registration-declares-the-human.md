# 116. One daemon, three clients: the registration declares the human

2026-09-10 · relates to 5, 68, 100

**Context:** the board refused every `ask` from Codex and OpenCode, because the guard against a session with nobody watching reads `CLAUDE_CODE_ENTRYPOINT`, a variable only Claude Code exports, and `install.sh` registered the shim with `claude` alone; the alternative on the table was a browser-presence handshake, a nonce page opened before every board and awaited. **Decision:** `install.sh` registers the shim with every client it finds on `PATH` (`claude mcp add`, `codex mcp add`, one key in `~/.config/opencode/opencode.json`) and refuses only when it finds none; the Codex and OpenCode registrations carry `CLAUDE_BOARD_CLIENT`, and a non-empty value passes the guard, so the registration itself is the declaration that a human is at the keyboard, made once by whoever installs, never inferred per call; the manual is copied to `~/.agents/skills/` too, where Codex looks. **Consequences:** a handshake that would open a tab on an unattended machine to find out nobody is there is not built; `codex exec` and `opencode run` load the same registration and pass, the same residual gap `/loop` already is, closed per run by disabling the server or by `CLAUDE_BOARD_HEADLESS=1` where the client passes its environment through; and Codex hands a stdio server only an allowlist of the parent environment, so the `env` table is the declaration's only way in there.
