# 150. One board per mission, each round its session's

2026-11-11, amends 69, 131, 134, 141

**Context:** each session minted its own board, so a mission's grill rounds and its build's landing brief sat on different pages and its card linked only the latest. A board was one conversation's: one folder bound at its first post (`assertCwdNotRetargeted`), one session (131), a boundary that closed every open round on it (69), and a post from a session bound elsewhere refused with "ask with fresh" (141). Rejected: the shim choosing the board, which a session joined through another client (the mission skill's own commands) never tells it; folding the boards older missions already hold, which is out of scope. **Decision:** the daemon chooses. A post from a session bound to a mission, naming no mission, lands on the mission's board, the latest board it links that is still stored, whatever board the post names; a mission with none gets one at that round. A post that moved answers `moved: true`, the shim takes that board as its own, and the rounds the session left open on the board it moved from close. Each round records the session that posted it (`session: { pid, procStart, id }`) and, where it differs from the board's, the folder its file references read from (`cwd`): a session bound to the board's mission posts from its own folder. Only the session that posted a round amends it, so another session's first question opens a round of its own; a post carrying `fresh` (the shim sends it on a `fresh` ask and after a mission join or leave) never amends and closes the posting session's other open rounds on that board in the same write; `POST /api/board/:id/abandon` naming `session` closes only that session's rounds. What a board owes (answers, comments) rides only its own session's packets. A takeover hands the giver's open rounds to the taker (`session` rewritten, `handedFrom` the giver's id), so the PM's answer on them rides the taker's next packet. Needs you reads the newest round of each session on a board, not the board's newest alone (134). **Consequences:** a mission's card links its one board; rounds from before this carry no session and are the board's first poster's; a post naming its mission explicitly keeps the board it names; posting on a board the size of the largest mission's boards merged (34 rounds, 4.4 MB) takes about 0.1 to 0.2 seconds, so rounds stay in one document; the taker learns of a handed round from its next packet, or by reading the board.
