# 62. Third-party rendering code is vendored, not depended on

2026-08-09

**Context:** closing the markdown ceiling (`src/markdown.mjs:9-11`) and giving code blocks syntax highlighting both wanted a real parser, but the repo has no bundler, no `node_modules` and no package dependencies, and its daemon source is hashed into `install.sh`'s payload digest (entry 15). **Decision:** vendor `marked@18.0.9` (MIT, zero runtime deps, one self-contained 41.9 KB ESM file) and `prismjs@1.30.0` (MIT, self-contained 19.5 KB core plus one grammar per language `langForPath` names) into `src/vendor/`, each at a pinned version with a recorded sha256 a check asserts offline. Corrected on landing: prismjs 1.30.0 ships no ESM build at all — its core is UMD and every grammar file assumes a shared `Prism` global, which under `"type": "module"` exports nothing and throws — so the vendored prism bytes are upstream's, unmodified, carrying a `.cjs` extension and reached through a hand-written ESM loader (`src/vendor/prism/index.mjs`) over `createRequire`. `marked` needed none of that. **Consequences:** the zero-dependency posture becomes zero-*installed*-dependency; the payload digest changes, so `./install.sh` is required rather than a bare kickstart; and `src/markdown.mjs` keeps ownership of `slugify` and of raw-HTML escaping through marked renderer overrides, because six modules and the archive id guard resolve `section` references through the existing slug scheme.
