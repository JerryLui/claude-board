# 149. Ten background sessions work at once, fourteen alive; the PM's tab holds no slot

2026-11-09, amends 129, 148

**Context:** at eight working and twelve alive (148) launches queued while the PM's own tabs, each bound to a mission by `/mission NAME`, held slots the Master Chief's background sessions needed. Those tabs are the PM's attention, not the load the caps meter, and the session watcher already tells them apart: each snapshot entry is `interactive` or `bg`. **Decision:** `MAX_WORKING` is 10 and `MAX_ALIVE` 14, the PM's pick. The launch caps' counts (`live`, and the launch check) skip a mission whose bound session the latest snapshot lists `interactive`; `listed()` carries each entry's `kind` for it. A launch's bare reservation and a session the snapshot does not list still count, and while the watcher reads down every live session counts. Rejected: counting tabs at a higher cap, which still lets the PM's tabs queue background work. **Consequences:** a tab joined to a mission no longer holds a slot, so up to ten background sessions work beside any number of tabs, against the heavy gate's memory budget; `~/.claude/scripts/board-wait.mjs` and the Master Chief's Caps rule hold the numbers too and change with this, after `./install.sh` has put them in the running daemon.
