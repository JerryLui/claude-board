# 146. A Claude Code session whose wait ended keeps an answer watch on the round, and the watch spends it

2026-11-04, narrows 47; widens 107; relates to 115, 145

**Context:** a Send after the wait ended reached the session only if it asked again (the next packet) or thought to `read`, so a reviewer who answered an hour late sat with nobody acting on it; the alternatives on the table were letting the late Send ride the next round and having no clock at all. **Decision:** a Claude Code shim's `timeout` packet names `watch`, the command of `bin/watch.mjs` for that board and round, which the session runs as one background call: it polls `POST /api/board/:id/collect` every 30 s for up to 24 hours and exits once the round is sent, printing the round's packet, and the collect spends the round on the `answersDelivered` ledger as a packet leaving would, so the next packet carries none of it; `delivered: true` when that packet came first. A late pick that differs from a default already built, fired or merged goes to the PM as a question; nothing built is undone. Rejected: a pure read for the watch (`read`, 115), which left the same answers to ride the next packet as well. **Consequences:** the wake is Claude Code's alone, since it rests on Claude Code re-invoking a session when a background call ends, so a Codex or OpenCode shim names no watch; a Send after the 24 hours is stored and readable, and reaches the next packet or `read`.
