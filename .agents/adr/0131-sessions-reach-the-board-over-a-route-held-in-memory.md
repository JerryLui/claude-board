# 131. Sessions reach the board over a route, held in memory

2026-10-29, relates to 5, 123, 125, 128, 129; amended by 141

**Context:** the Missions view showed only sessions a mission launched; the person's hand-started agent tabs, and a background job blocked on a usage limit or a browser, were invisible, so a session waiting on a board round read as just busy. Claude Code keeps its own list of sessions, but the board serves every agent, and a session's name is its first prompt, which can carry case content. Rejected: the daemon reading Claude's session folder itself, which ties a public, agent-neutral board to one agent's private layout; storing sessions like missions, which puts first prompts on disk for 30 days; joining a tab to a mission by its name. **Decision:** a watcher outside the board posts a full snapshot of the running sessions to `POST /api/sessions` (secret only) on an interval, and the daemon holds it in memory, replacing it whole: no session's name or blocked reason reaches the store, a board or mission record, a log line or a notification, and a restart forgets them. Two missed intervals read the watcher down and drop the list. Each listed session no mission holds or held (by its session id, or a job id that is that id's first 8 characters) is a tab card in the Missions view's columns: needs you while a round that wants its answer sits on a board it posted or it is a blocked job, working while busy, waiting (its turn) while idle. A board post names its session by pid and process start; the daemon records the matching listed session's id on the board, and a board keeps the session that first posted to it, so a reused pid, starting at another time, never inherits a round or revives a card. Tab cards take Stop and comment orders as a mission's card does (ADR 125), held with the session. **Consequences:** with no watcher running the board shows no tabs and says the watcher is down, and the page is only as fresh as the watcher's interval; a needs-you tab counts toward the menu bar's needs-you count, and no tab counts toward the launch caps (ADR 129) or speaks a notification (ADR 128); a round posted before its session is listed links by pid and start until a later post fills the id.
