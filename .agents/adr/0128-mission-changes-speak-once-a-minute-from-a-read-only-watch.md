# 128. Mission changes speak once a minute, from a read-only watch

2026-10-28, widens 56; relates to 71, 72, 94, 106

**Context:** a session that dies or goes silent changes no byte on disk, so no route can announce a stall, and the person and the Master Chief need to hear when a mission needs the person, stalls or lands. ADR 71 rules out anything deleting on a schedule. **Decision:** the daemon reads every mission's derived state every 30 seconds and writes nothing. A change no write published goes out as `missions` on the daemon-wide stream. A mission turning needs-you, stalled or landed joins a batch that speaks once, a minute after its first entry, as one notification naming the work or counting it ("2 missions need you, FRONT_AGENT landed"). The first read after a start is the baseline and says nothing. The Banner level's Off silences it; every On level speaks, since those levels are about which board is being looked at and a mission is no board (106). The line crosses into the launcher as the `missions` row's one argument, under a second filter pattern beside the folder name's: the same set plus the comma, under 120 characters, in C (`is_safe_mission_line`) and in JS (`isSafeMissionLine`), which must match. The Popover gains one row, "Missions: 2 need you, 3 working", from `/api/waiting`'s `missions` counts, opening the home page. **Consequences:** a timer now reads the store, which 71 never forbade, while deleting stays a click; the second pattern belongs in review with the cue and folder filters (56), and a name outside it is counted, never shown; the notification carries no click, since the launcher opens board URLs alone; the Status item's glyph draws no mission count (94), only the row does.
