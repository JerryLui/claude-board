# 154. A saved mock is the page's own file and runs its scripts; a round's file stays script-free

2026-11-16, relates to 22, 32, 78, 95, 108, 120, 122, 152

**Context:** every file the board saved was a script-free copy: Download round (152) and Pull-out's Download both wrote a mock as its `srcdoc` with every script removed, in a frame sandboxed with nothing allowed, under a policy that admits no script. That holds for a static mock and fails for a page that draws itself by script, which is what the render templates post: saved, such a page showed its diagrams as source text and an empty contents list, so the file could not be handed to anyone. The board cannot fix that by copying what the stage drew, because the stage is a sandboxed frame at an opaque origin (32, 78) and the parent sees none of its document. Why not a drawn still copy, why the board fetches no library a mock names, and why the file's policy is this one: DESIGN.md. **Decision:** two kinds of saved file. A mock saved alone, from its Pull-out or as the one mock of a round drawn full page, is the mock's own page: a four-line head (doctype, UTF-8, the file's policy, the stage's margin reset, so it lays out as it does in a stage), then the vendored diagram engine's text in one inline script wherever the board lent that stage the engine (108), then the block's `html` as the stage holds it, scripts included. The policy is a meta content-security-policy, `default-src 'unsafe-inline' https: data: blob:`, ahead of every script in the file: what is written in the file runs, `data:` and `blob:` load, an `https:` address loads, and no `file:` address does, nor the page's own folder (no `'self'`), nor code built from text (no `'unsafe-eval'`, as on the board). The engine runs first, so a mock that looks for `window.mermaid` before loading or importing one finds it, exactly as it does in a stage, and nothing is fetched. The tab reads the source back out of the stage's `srcdoc`, where a page holds it once (122), and the engine from the board's own copy beside the page. Nothing else of the board's rides: no stage script, no stylesheet, no comment. The tab hands the browser that file as plain bytes for a few seconds, so its address saves and never draws at the board's origin. A question round's file, and one board diagram's, stays as it was: the copy with no script and a policy that admits none, a mock inside it a still copy. **Consequences:** a saved mock runs its scripts wherever it is opened, at that file's origin with no sandbox, where the board ran them boxed in (22, 78): the file is as trusted as the session that wrote the mock, and opening one is opening a page that session authored. Opened from disk it is a `file:` page, which a browser lets load any other file on that disk as a script or an image; the policy is what stops that, the same reach an archive is refused (`SECURITY.md`). It stops nothing else: a script in the file can still send what the page holds to an `https:` host, and an address a mock names by `http:` (a server on the reader's own machine) no longer loads from the saved file. A round's decisions never sit beside a running script, since the file that carries picks and comments admits none. A full-page round's file no longer lists the comments made on its mock, and no longer prints fitted to one page: it is the page and prints as itself. A diagram-drawing mock's file weighs the engine, about 3.5 MB. An engine text holding a script tag cannot be written inline and is refused; a check pins that the vendored one holds none. Known limit: a library a mock names by web address other than the diagram engine stays a web address, so that part of the saved page needs a connection, until that library is vendored beside the engine.
