# 140. A mission card reads from facts: an open round ahead of stalled, PR states from GitHub, a gone session said

2026-10-30, amends 123, 129; relates to 125, 128, 134

**Context:** a mission's card read stalled over needs you, so a round asking the person hid behind a session that had stopped waiting on it, and the person learned of the question only by opening the board; its PR chips showed whatever state the session last wrote, which went stale or wrong the moment checks ran; and a session whose process had died read only as stalled, with no word of when it was last heard or a way to look again short of the 5 s cache and the minute's watch. Rejected: keeping stalled first and nudging the session to re-ask, which needs a live session to do it; and PR states from the session's own words with a staleness mark, which keeps the words. **Decision:** the view reads released, then needs you (a linked board's newest round open and asking, 134, whether or not the session still waits on it), then stalled, then the stored state. A PR's `state` and `head` in the view come only from facts the session watcher posts, `POST /api/mission/:key/facts`, read from GitHub at the PR's head commit (`draft`, `open`, `green`, `red`, `merged`), stored as `prFacts` and replaced per repo and number; before a PR's first fact it reads `checking`, and a fact for a PR the mission does not list is dropped. A session names its PRs by `{ repo, number, url }`; a `state` it sends is still taken from an older writer and dropped. A view whose bound session is gone carries `gone: { lastSeenAt }`, and its card says "Session gone, last seen" that time, with a Check again that posts `POST /api/mission/:key/recheck`, which drops the daemon's missions cache and answers the view read now; the cookie may make that call, since it writes nothing. **Consequences:** a PR chip is only as fresh as the watcher's last post, and reads `checking` while no watcher runs; a facts post leaves `updatedAt` alone, so a reading never moves a card up the list or resets its age; a session silent past 15 minutes while its round asks now counts as needs you, not working, toward the launch caps. A view's `prs` writes back as read: the `head`, `checkedAt` and `checking` it carries are dropped like a sent `state`. A PR stored with a `state` before facts existed reads that state until its first fact, and keeps it when the list is rewritten; since no write stores one, it is never a live session's word. A session that dies while its mission reads needs you leaves the card in needs you, with its gone line, and the missions watch speaks it as stalled.
