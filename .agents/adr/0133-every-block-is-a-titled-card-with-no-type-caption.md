# 133. Every block is a titled card, with no type caption

2026-10-29, amends 110; relates to 28, 132

**Context:** every block opened with a type caption (Markdown, HTML stage, Compare, Mermaid, Question), which named what the reader could already see, while the evidence card's look, a title with a status chip, read better; the person asked for one look across every block, field and card rather than for screenshots alone. Rejected: flat sections, text set on the page with no card, which leaves two kinds of block. **Decision:** every block renders as a card that opens with a head row, its title (the block's `title`, a question's prompt, else a markdown block's opening heading moved out of its body, else none) and its status chip at the card's right edge (`status`, or a question's Answered or Deferred, live as it is answered); then the optional summary, the content and a closed Details fold (`detailsLabel` or "Details"). Long text folds behind "Show the rest"; a question that takes several picks says so under its prompt; a titled item in a question's context wears the same head at a smaller scale, and an untitled one stays bare prose. No block carries a type caption. The head is chrome, never a comment target. A `dom` anchor stored against the captioned markup, which counted the caption as the section's first child, resolves through a view of the section with the caption put back, tried after today's section. **Consequences:** a stored board renders in the new look with no migration, and its comments land where they did; the legacy view stays as long as a stored board may carry such an anchor; a markdown block whose body opens with a heading shows it as the title, its `id` kept, so a link to it still lands.
