# Contributing

**A personal project, not a maintained product.** [SECURITY.md](SECURITY.md#reporting)
already says this for security reports; the same posture holds everywhere else in this
repo.

## Issues

Welcome: bugs, confusion, a doc that's wrong, a feature you want. Use the
[bug report template](.github/ISSUE_TEMPLATE/bug_report.yml) if it fits, or open a
blank issue if it doesn't.

## Pull requests

Welcome, with no review SLA. A PR may sit for a while before anyone looks at it, and
being looked at is not a promise of merge. Small and scoped reviews faster than large;
if you're planning something substantial, open an issue first so the direction gets
checked before the work does.

## Code of Conduct

There deliberately isn't one. A CoC governs a community; this repo has one maintainer
and no community to govern, so posting one would name an enforcement process that
doesn't exist. Baseline expectation without one: be civil in the issue tracker. If a
community forms around this project, that changes and this file changes with it.

## Support

Same line as SECURITY.md: no support commitment and no response-time promise. Issues
get answered when there's time for them; that time is not scheduled.
